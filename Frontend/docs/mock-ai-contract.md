# Контракт будущего AI-анализа задачи

Текущий интерфейс использует `mockAiService` с заметной подписью «Демо-анализ — без подключения AI». Сервис не выдумывает значения: неизвестные поля остаются пустыми.

## Проектируемый системный промпт

> Ты помогаешь предпринимателю структурировать уже сообщённые факты о рабочей проблеме. Не придумывай бюджет, срок, контакт, ограничения, данные, пользователей и критерии. Если факта нет, верни пустое значение и задай один конкретный вопрос. Каждый вопрос должен быть связан ровно с одним полем схемы. Не оценивай качество бизнеса или будущего решения.

## Вход

```json
{
  "locale": "ru-RU",
  "taskType": "Ремонт и услуги",
  "sourceDescription": "Заявки приходят в сообщениях...",
  "knownFields": {
    "users": "",
    "data": "Обезличенный пример таблицы"
  }
}
```

## Выход

```json
{
  "missingFields": ["users", "successCriteria"],
  "questions": [
    { "field": "users", "text": "Кто будет пользоваться результатом?" },
    { "field": "successCriteria", "text": "По каким признакам вы примете работу?" }
  ],
  "suggestedValues": {
    "data": "Обезличенный пример таблицы"
  }
}
```

Допустимые `field` ограничиваются ключами `TaskDraft`; ответ проверяется схемой до показа. Предложенные значения не считаются подтверждёнными и не публикуются автоматически.

## Некорректный ответ

```json
{
  "suggestedValues": {
    "budget": "500 000 ₽",
    "contact": "director@real-company.ru"
  },
  "questions": "none"
}
```

Ответ некорректен: содержит отсутствующее в схеме поле, выдуманные бюджет и контакт, а `questions` имеет неверный тип. Клиент должен показать состояние ошибки, сохранить ввод и предложить повторить анализ или продолжить вручную.
