# PRAKTIKA — frontend-демо

Рабочий интерфейс образовательной платформы «Реальные задачи. Практические навыки». Малый бизнес формулирует задачу, студенческая команда откликается, бизнес вручную выбирает команду, а наставник проверяет учебные этапы.

## Запуск

Требуется Node.js 20.19+ или 22.12+ (требование Vite) и npm 10+.

```bash
npm install
npm run dev
```

Production-сборка демо: `npm run build`. Тесты доменной логики: `npm test`. Проверка TypeScript: `npm run typecheck`.

## Деморежим

Регистрация не требуется. Роль переключается в правой части верхней панели: «Бизнес», «Студент», «Наставник». Данные синтетические, хранятся в `localStorage` текущего браузера и не синхронизируются между устройствами. Переключатель роли — демонстрационный, настоящей авторизации и защиты маршрутов нет.

Основной сценарий:

1. В кабинете бизнеса создать или дополнить задачу.
2. Ответить на контекстные вопросы демо-анализа, проверить карточку и подтвердить группы сведений.
3. Опубликовать задачу и найти её в каталоге.
4. В роли студента отправить отклик.
5. В роли бизнеса открыть предложения и вручную выбрать одну или несколько команд.
6. В учебном пространстве отправить этап в роли студента и проверить его в роли наставника.

Сброс демоданных находится внизу боковой панели и требует подтверждения.

## Рейтинг готовности

`calculateReadiness(task)` — единая чистая функция в `src/domain/readiness.ts`. Используется бинарная шкала: критерий получает весь вес, только если связанные поля непустые, не содержат заглушку «не указано» и явно подтверждены человеком.

| Критерий | Баллы |
|---|---:|
| Контекст и потребность | 20 |
| Данные и материалы | 20 |
| Ожидаемый результат | 15 |
| Критерии успеха | 15 |
| Ограничения | 10 |
| Пользователи | 10 |
| Связь с бизнесом | 10 |

Уровни: 0–39 «Черновик», 40–69 «Рабочая», 70–89 «Готовая», 90–100 «Приоритетная». Это индикатор полноты подтверждённых сведений, а не AI-оценка качества. Изменение поля сбрасывает подтверждение связанного критерия. Жизненный цикл публикации отделён от рейтинга: опубликованный черновик остаётся видимым и принимает отклики; при редактировании сохраняется прежний опубликованный снимок до нового подтверждения.

## Структура

- `src/domain` — типы и чистая логика рейтинга;
- `src/features` — экраны бизнеса, студента, задач и обучения;
- `src/components/ui` — общие индикаторы и доступное модальное окно;
- `src/layouts` — рабочая оболочка и ролевая навигация;
- `src/demo-data` — связанные синтетические задачи, команды, отклики и проект;
- `src/services` — асинхронная граница и `mockAiService`;
- `src/store` — Zustand-состояние, версионированное безопасное хранение;
- `docs/mock-ai-contract.md` — проектируемый контракт будущей AI-интеграции.

## Будущие подключения

Backend подключается за асинхронной границей `src/services/demoApi.ts`; хранилище можно заменить API-репозиторием без изменения доменной функции рейтинга. Настоящий AI должен вызываться только через сервер: клиент передаёт структуру из документа контракта, сервер валидирует ответ и возвращает безопасный JSON. В клиентском коде нет ключей и платных вызовов.

Это локальное продуктовое демо, не production-ready сервис. Оно не содержит сервера, реальной авторизации, оплаты, синхронизации и внешней аккредитации навыков.
