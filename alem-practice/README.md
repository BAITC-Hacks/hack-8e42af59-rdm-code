# Alem Practice

Платформа учебной практики: бизнес описывает задачу, студент предлагает решение, выполняет этап и получает подтверждённый результат для портфолио.

## Первый запуск на Windows

Нужен Node.js 22.14+ и npm. Откройте терминал **в папке `alem-practice`**:

```powershell
npm ci
Copy-Item .env.example .env
npm run setup
npm run dev
```

Откройте http://127.0.0.1:3000. Для уже настроенного проекта достаточно `npm run dev`. Не заменяйте свой `.env` при каждом обновлении.

Для выступления используйте готовую сборку:

```powershell
npm run build
npm start
```

После получения обновлений остановите сервер, выполните `npm ci`, `npm run db:generate`, `npm run db:migrate`, затем `npm run db:seed` и `npm run build`. Seed добавляет недостающие примеры, сохраняя существующие задачи и профили. Перед миграцией сохраните резервную копию `prisma/dev.db` при остановленном сервере.

## Открыть с телефона или другого компьютера

Все устройства должны открывать **один сервер**, чтобы видеть общие аккаунты и проекты.

```powershell
npm run build
npm run start:lan
```

Команда покажет локальные адреса компьютера и разрешит вход с них. Подключите телефон к той же сети и откройте адрес сетевого адаптера, через который компьютер подключён к роутеру, например `http://192.168.1.25:3000`. На телефоне `localhost` указывает на сам телефон, поэтому используйте IP компьютера.

Если порт 3000 занят другой копией проекта:

```powershell
$env:PORT='3002'
npm run start:lan
```

Адрес тогда будет заканчиваться на `:3002`. После изменения сети перезапустите команду: IP может измениться. `npm run dev:lan` запускает тот же сетевой режим с обновлением кода при разработке.

Компьютер должен быть включён, терминал — работать. Если Windows запросит доступ Node.js к сети, разрешите его для используемой доверенной частной сети. Если телефон не подключается, проверьте одинаковую сеть, порт, правила брандмауэра и изоляцию клиентов на Wi-Fi хакатона. Некоторые гостевые сети запрещают устройствам обращаться друг к другу.

Этот HTTP-режим предназначен для демонстрации в доверенной локальной сети. Публичный запуск с HTTPS описан в [DEPLOYMENT.md](./DEPLOYMENT.md).

## Вход и аккаунты

- Регистрация по имени, роли, **логину и паролю**. Номер телефона и SMS не нужны.
- Логин: 3–24 символа, латинские буквы, цифры и `_`, начинается с буквы. Регистр не важен: `MyTeam` и `myteam` — один логин.
- Пароль: 12–128 символов; можно использовать длинную фразу. При регистрации нужен повтор пароля.
- Профиль, задачи и отклики хранятся в серверной SQLite-базе. При входе с другого устройства используются те же данные.
- Сессия каждого устройства отдельная, срок — 7 дней. Обычный выход завершает текущую сессию. Кнопка в профиле позволяет выйти со всех устройств.
- Восстановление и изменение пароля через интерфейс пока не реализованы. Сохраните пароль в своём менеджере паролей.

Пароли хешируются scrypt с индивидуальной случайной солью: `N=32768, r=8, p=3`, один из вариантов [OWASP Password Storage Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html). Сессионные токены также хранятся в базе в виде хешей; cookie — HttpOnly, SameSite=Lax и Secure при HTTPS `APP_URL`. Есть проверка источника изменяющих запросов и ограничения попыток входа в базе: 10 на логин и 120 на экземпляр приложения за 15 минут.

Старые профили сохранены миграцией. Если старая сессия ещё действует, в профиле можно задать логин и пароль, сохранив команду и работу; прежние сессии завершатся. Если старой сессии нет, автоматическое присвоение профиля по телефону или имени недоступно. Создайте новый аккаунт либо организуйте проверенный перенос через администратора. Новым аккаунтам не назначаются общие или стандартные пароли. Старые SMS-маршруты удалены; переменные `AUTH_MODE` и `TWILIO_*` больше не используются.

## Возможности продукта

- 25 исходных задач в пяти направлениях и пять скачиваемых синтетических датасетов.
- Объёмная образовательная иллюстрация, плавающие элементы, наклон карточек и плавные переходы. Анимации можно выключить; системное сокращение движения учитывается автоматически.
- Контрастные карточки и интерактивная диаграмма направлений. Числа в каталоге и прогресс практики вычисляются из данных.
- Личный профиль: имя, город, место обучения, навыки, портфолио, команда/организация. Публикацию в сообществе включает владелец.
- Черновики и отклики доступны владельцу и участникам соответствующего проекта. Данные входа не выдаются публично.
- Конструктор задачи с AI/mock AI, подтверждением сведений и рейтингом готовности 0–100.
- Отклики, ручной выбор команд, отправка этапа, подтверждение бизнесом и однократное начисление 50 баллов.

Демо-команды и организации вымышлены и отмечены в интерфейсе. Новые профили заполняют сами пользователи; регистрация не удостоверяет личность. Размер команды указывает владелец; приглашения и совместное редактирование пока не реализованы. Старые mock-профили по умолчанию не показываются в сообществе, пока владелец не задаст пароль.

## Стек

Next.js App Router + React + TypeScript; Prisma + SQLite; Zod; Radix Dialog; Lucide. 3D-графика реализована CSS и SVG без тяжёлого WebGL-движка.

- `components/`: каталог, кабинеты, регистрация и профили.
- `components/learning-visuals.tsx`: диаграммы и прогресс.
- `app/studio.css`: обновлённая палитра, эффекты и адаптивные стили.
- `lib/auth.ts`: пароли, сессии, лимиты и разрешённые адреса.
- `lib/data.ts`: выдача данных с учётом доступа.
- `lib/actions.ts`: бизнес-правила практики.
- `prisma/`: схема, миграции и локальная база.
- `data/seed.json`, `data/extra-tasks.json`: 25 примеров.
- `public/datasets/`: учебные CSV/JSON.

## OpenAI: локальная настройка

Сохраните существующий `.env`: не копируйте шаблон поверх него. Добавьте или измените только настройки AI:

```dotenv
AI_MODE="live"
AI_PROVIDER="openai"
OPENAI_API_KEY=""
OPENAI_MODEL="gpt-4.1-mini"
```

Ключ вводится только локально в пустое значение OPENAI_API_KEY, никогда в чат, GitHub или переменную NEXT_PUBLIC.
Доступность модели, действительность ключа и баланс кредитов зависят от аккаунта и не гарантируются кодом.
`OPENAI_MODEL` можно изменить; старое `AI_MODEL` остаётся запасным именем настройки.
Для прежнего провайдера используйте `AI_PROVIDER=compatible` и `AI_BASE_URL`, `AI_API_KEY`, `AI_MODEL`.
После изменения окружения перезапустите сервер.

Явная проверка **одним платным запросом**, только после согласования расходов:

```powershell
npm run ai:check -- --live
```

Скрипт выводит только режим, модель, причину fallback и число вопросов. Ключи и тексты провайдера не печатаются.
Успех — `mode: live`, `provider: openai`. При ошибке возвращается ненулевой код завершения.
Он не проверяет баланс кредита. Схема интеграции основана на официальных документах
[Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs) и
[GPT-4.1 mini](https://developers.openai.com/api/docs/models/gpt-4.1-mini).

При отсутствии ключа, 401/429, отказе модели, неверном JSON, сетевой ошибке или timeout сайт продолжает
работать с детерминированным fallback. Ответ помечен `mode: mock` и `diagnostics.fallbackReason`;
это не настоящий ответ OpenAI. Есть лимит входа, 3–9 разных вопросов, проверка схемы и ссылок на источники,
12 секунд на попытку, максимум один повтор временной ошибки, максимум 3500 выходных токенов.
Запрос отправляется только по действию пользователя. Ответы OpenAI не сохраняются у провайдера через
Responses application storage (`store:false`); это не обещание отсутствия иных служебных журналов провайдера.
Локальная база хранит исходное описание и введённые ответы до обращения к AI.

## Рейтинг, публикация и сохранение

Сервер рассчитывает рейтинг: контекст 10 + потребность 10 + данные 20 + результат 15 + критерии 15 +
ограничения 10 + пользователи 10 + контакт 5 + взаимодействие 5 = 100.
Учитываются только заполненные и подтверждённые поля. Контакт должен содержать email, HTTP(S)-ссылку
или телефон; «білмеймін», «не знаю», пустые строки и одна пунктуация не дают баллов.
Это проверка полноты, а не семантическая оценка качества или достоверности.
Уровни API сохранены: draft (0–39), working (40–69), ready (70–89), priority (90–100).
Ответ `/api/data` дополнен расшифровкой `readiness`: баллы по полям, missingFields и советы.

Редактирование карточки снимает публикацию до нового **Подтвердить сведения → Опубликовать**.
Нерассмотренные изменения не попадают в каталог. Задача и существующие предложения не удаляются.
Публикация требует подтверждённой потребности, но не высокого рейтинга. Низкий рейтинг не блокирует отклики.
Каталог сортируется по убыванию рейтинга, затем даты, затем по ID для одинаковых значений;
поиск и фильтры остаются в существующем клиенте.

Повтор идентичного предложения той же команды возвращает существующую запись, в том числе при
параллельной отправке или после перезапуска. Другую идею/план можно отправить отдельным предложением.
Обычные ссылки — HTTP(S); старые учебные `/demo/prototypes/...` поддерживаются через backend adapter.
Баллы практики отделены от рейтинга: +50 после подтверждения этапа — наше правило MVP.
Проверки прав, решения и начисления выполняются транзакционно, награда уникальна по этапу.

Первоначальные описания и ответы можно получить через приватный `GET /api/drafts`.
Автоматическое восстановление незавершённой формы в интерфейсе ещё требует draft picker от frontend команды.
Полный контракт, примеры запросов, ограничения и задачи для frontend: [docs/BACKEND_CONTRACT.md](./docs/BACKEND_CONTRACT.md).

## Проверка

```powershell
npm run typecheck
npm run lint
npm test
npm run build
npm run test:http
npm run test:auth-http
```

Автоматические тесты работают с временными базами. HTTP-сценарии сами запускают готовую сборку: test:http — на порту 3107, test:auth-http — на 3001 и удаляют свои базы после проверки; действующие аккаунты презентации они не меняют. Проверяют в том числе две независимые сессии одного аккаунта и полный цикл практики. Для другого порта используйте `TEST_HTTP_PORT` или `SMOKE_PORT` соответственно. scripts/smoke-http.mjs вызывается только из изолированного test:http.
