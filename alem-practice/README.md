# Alem Practice

Локальный MVP для образовательного хакатона AI Sana. Бизнес превращает потребность в понятное практическое задание, студенты предлагают решение, бизнес выбирает команды и подтверждает результат этапа.

## Быстрый запуск

Нужен Node.js 22.14 или новее в ветке 22. Команды выполняются в этой папке.

```powershell
npm ci
Copy-Item .env.example .env
npm run setup
npm run dev
```

Если `.env` уже настроен, сохраняйте его; повторно копировать шаблон не нужно. Откройте http://127.0.0.1:3000. База `prisma/dev.db` уже создана в текущем рабочем проекте. Повторный `npm run db:seed` добавляет отсутствующие исходные записи и не перезаписывает существующие.

Сборка для показа без компиляции страниц на ходу:

```powershell
npm run build
npm start
```

Перед `npm start` остановите сервер разработки на порту 3000. SQLite сохраняется между перезапусками. Скопируйте `prisma/dev.db`, если нужна резервная копия результатов демонстрации. Сервер слушает только 127.0.0.1.

## Что работает

- Каталог опубликованных задач, поиск по названию/компании/навыкам, фильтры по направлению и готовности, сортировка по рейтингу.
- Три шага конструктора: свободное описание, минимум три вопроса, редактируемая карточка.
- Ручное подтверждение сведений, пересчёт рейтинга и отдельная публикация.
- Учебные результаты: навыки, необходимые знания, результат для портфолио.
- Кабинеты бизнеса и команды, неограниченное число предложений с планом, сроком и ссылкой.
- Ручной выбор одной или нескольких команд, отклонение и возврат на рассмотрение.
- Отправка результата первого этапа и +50 баллов практики после подтверждения бизнесом.
- Явно подписанные внутренние учебные ссылки на прототипы.
- Пять организаций, пять черновиков, пять задач, пять команд, пять откликов.

## Стек и структура

Next.js App Router / React / TypeScript; Tailwind CSS 4; настраиваемые Button и Dialog в стиле shadcn/ui на Radix; иконки Lucide. Next.js Route Handlers выполняют серверную валидацию и операции с SQLite через Prisma 6.19.2. Версии фиксирует package-lock.json. CSS разделён на базовую оболочку, рабочие формы и небольшие визуальные уточнения.

- `app/` — страницы и HTTP API.
- `components/` — каталог, конструктор, кабинеты, общие элементы.
- `lib/domain.ts` — типы, Zod-схемы, формула рейтинга.
- `lib/actions.ts` — серверные переходы и транзакция начисления баллов.
- `lib/ai/` — AI-промпт, контракт, demo/live-адаптер.
- `prisma/` — схема, миграция, идемпотентный seed.
- `data/` — синтетические наборы и готовые ответы для защиты.
- `tests/` — тесты рейтинга, AI-контракта и сквозного серверного сценария.
- `VERIFICATION.md` — фактические результаты проверки и ограничения.

## Рейтинг и подтверждения

Контекст 10 + потребность 10 + данные 20 + ожидаемый результат 15 + критерии успеха 15 + ограничения 10 + пользователи 10 + контакт 5 + взаимодействие 5 = 100.

Баллы получают только заполненные и подтверждённые поля. Пустые строки и «не знаю», «потом», «не указано», «-» не учитываются. Контакт требует email, ссылки или номера. Проверка полноты эвристическая: она не доказывает истинность информации и не является семантической оценкой качества бизнеса. Измеримость критериев предлагается подсказкой; окончательную корректность проверяет человек.

Изменение подтверждённого поля снимает его подтверждение и его баллы. После сохранения требуется повторное действие «Подтвердить сведения». Уровни: 0–39 черновик, 40–69 рабочая, 70–89 готовая, 90–100 приоритетная. Уровень «Черновик» независим от статуса публикации. Любая опубликованная задача доступна всем командам, в том числе при низком рейтинге.

Баллы практики команды — другая сущность. Они начисляются за подтверждённый бизнесом этап. `Award.milestoneId` уникален, запись начисления и увеличение баланса выполняются в одной транзакции. Повторное подтверждение не удваивает баллы.

## Демонстрационные роли

В верхней панели выберите «Студент / Бизнес», затем организацию или команду. Сервер проверяет соответствие выбранного профиля операции. Это открытая демонстрация без регистрации и реальной аутентификации: профили не являются защищёнными аккаунтами. Не размещайте здесь реальные персональные или коммерческие сведения.

Выбранный профиль сохраняется только как настройка интерфейса в sessionStorage. Задачи, предложения и баллы всегда хранятся в SQLite. На странице «Как проходит практика» доступен явный сброс только исходных учебных карточек и откликов; новые записи остаются. В текущей базе также сохранена шестая задача после проверки полного сценария.

## AI

По умолчанию `AI_MODE=mock`; ключ и интернет не нужны. В demo-режиме вопросы зависят от недостающих полей и тематики описания, ответы переносятся в соответствующие поля. Исходное описание используется как черновой контекст и потребность без выдумывания фактов. Неизвестные сведения остаются пустыми. Mock не является языковой моделью.

Live-адаптер принимает провайдера с совместимым Chat Completions endpoint и JSON-ответами:

```dotenv
AI_MODE="live"
AI_BASE_URL="https://YOUR-PROVIDER/v1"
AI_API_KEY="YOUR-KEY"
AI_MODEL="YOUR-MODEL"
```

Настройки хранятся только в `.env`, который исключён из Git. После изменения настроек перезапустите сервер. Никакой провайдер не подключён заранее; реальный live-вызов без ключа не тестировался. Адаптер вызывает `${AI_BASE_URL}/chat/completions`, ждёт до 12 секунд на попытку и повторяет временный сбой один раз. При ошибке форму можно продолжить через явный demo-режим; ответы сохраняются в форме.

Промпт: `lib/ai/prompts.ts`. Вход: `{mode,draft:{id,text,industry},answers:[{id,questionId,text}],forceMock?}`. Questions-выход: `{questions:[{id,field,question,reason}],missingFields,mode}`. Card-выход: `{card:{title,context,need,data,expectedResult,successCriteria,constraints,users,contact,collaboration},evidence:[{field,sourceIds}],missingFields,mode}`.

Zod проверяет форму ответа и допустимые поля. Для каждого непустого поля проверяется наличие источника из входных записей. Такая проверка не гарантирует отсутствие выдумок; редактирование и ручное подтверждение остаются обязательными. Некорректный JSON, пустой ответ, тайм-аут и недоступность сервиса показываются пользователю как ошибка, а не как успех.

## API

`GET /api/data` возвращает актуальное demo-состояние, `POST /api/ai` формирует вопросы или карточку, `POST /api/action` принимает `{action,payload}`. Изменения требуют `x-demo-role` (`business`/`student`) и `x-demo-id` (идентификатор профиля). Команды: createTask, updateTask, confirmTask, publishTask, createProposal, decideProposal, submitMilestone, confirmMilestone, resetDemo. Поиск и фильтры каталога выполняются в интерфейсе по загруженным данным.

## Проверки

```powershell
npm run typecheck
npm run lint
npm test
npm run build
```

Тесты создают отдельную SQLite-базу в `tests/.tmp`, применяют SQL-миграцию, проверяют сценарий и удаляют только собственный временный файл. Рабочая база не меняется. Проверяются границы рейтинга, рост 20 → 60 → 100, снятие подтверждения, AI-контракт, запрет публикации без подтверждения, отклики при 20 баллах, несколько выбранных команд, отклонение всех, права demo-роли и однократность награды.

## Ограничения

Локальный хакатонный MVP; нет полноценной авторизации, загрузок файлов, чата и уведомлений. Данные синтетические. Внутренние страницы прототипов — подписанные учебные макеты. Входные CSV продаж и другие материалы описанных студенческих задач не приложены: платформа не выполняет эти задачи за студентов. SQLite-файл не рассчитан на эфемерную файловую систему serverless-хостинга; для облачного пилота нужны постоянное хранилище или PostgreSQL, настоящая авторизация и миграция ролей.

Сценарий защиты: `DEMO.md`. Дизайн и учебные поля конкретизируют кейс, а +50 за этап — наше правило MVP, не заданный организаторами размер награды.
