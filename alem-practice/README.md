# Alem Practice

Платформа учебной практики: бизнес описывает задачу, студент предлагает решение, выполняет этап и получает подтверждённый результат для портфолио.

## Быстрый запуск на Windows

Требуется Node.js 22 и npm. Откройте терминал в папке `alem-practice`:

```powershell
npm ci
Copy-Item .env.example .env
npm run setup
npm run dev
```

Откройте **http://127.0.0.1:3000**. Используйте именно этот адрес: он совпадает с `APP_URL`, по которому проверяется источник запросов. Для уже настроенного проекта достаточно `npm run dev`. Не запускайте два сервера на одном порту.

Для презентации без режима разработки:

```powershell
npm run build
npm start
```

После обновления существующего проекта остановите сервер, выполните `npm ci`, `npm run db:generate`, `npm run db:migrate`, `npm run db:seed`, затем сборку и запуск. Seed добавляет недостающие записи, сохраняя существующие данные.

## Что работает

- 25 исходных учебных задач в пяти направлениях: веб-разработка, аналитика данных, UX, бизнес-аналитика, образовательные технологии.
- Пять скачиваемых синтетических датасетов; ссылки находятся в новых карточках.
- Объёмная CSS-иллюстрация образовательного пути, наклон карточек от указателя, анимации страниц и окна входа. Есть мобильная версия и поддержка `prefers-reduced-motion`.
- Регистрация студента или представителя бизнеса по одноразовому коду, повторный вход, постоянная сессия, выход.
- Личный профиль: имя, город, место обучения, описание, навыки, портфолио, команда/организация. Публикация в сообществе включается самим пользователем.
- Телефон входа скрыт от других участников. Черновики и отклики доступны только владельцу или участникам соответствующего проекта.
- Конструктор задачи с AI/mock AI, подтверждением сведений и рейтингом 0–100.
- Отклики, ручной выбор нескольких команд, отправка этапа, подтверждение бизнесом, однократное начисление 50 баллов.

Демо-организации и команды вымышлены и отмечены в интерфейсе. Новые профили создают пользователи; тестовый вход не подтверждает личность или владение номером. Численность команды указывается владельцем; приглашения и совместное редактирование команд пока не реализованы.

## Вход без SMS-сервиса

По умолчанию `AUTH_MODE=mock`, `ALLOW_MOCK_AUTH=true`. Код показывается в окне с надписью **«SMS не отправлено»**. Для демонстрации используйте вымышленные номера, например `+15555550123`.

Код случайный, действует 5 минут, используется один раз. Есть максимум 5 попыток проверки и пауза 60 секунд между отправками, 5 запросов в час на номер и 100 на весь экземпляр приложения. Лимиты хранятся в SQLite. Тестовый режим разрешён только при локальном `APP_URL`; сервер по умолчанию слушает `127.0.0.1`. Не публикуйте локальный mock через туннель или прокси.

Аккаунты mock и Twilio разделены: тестовый код не даёт доступ к аккаунту, ранее подтверждённому настоящим SMS. После переключения режима потребуется зарегистрировать профиль с реальным SMS; тестовые профили не переносятся автоматически.

## Подключение настоящих SMS

Подготовлен серверный адаптер **Twilio Verify**. Реальная отправка не проверялась: оплаченного сервиса и ключей в проекте нет.

1. Создайте Verify Service в Twilio и настройте разрешённые страны отправки, доступность направления и лимиты расходов.
2. Заполните локальный `.env` или секреты окружения хостинга:
   - `AUTH_MODE=twilio`
   - `ALLOW_MOCK_AUTH=false`
   - `APP_URL=https://ваш-домен`
   - `TWILIO_ACCOUNT_SID`
   - `TWILIO_AUTH_TOKEN`
   - `TWILIO_VERIFY_SERVICE_SID`
3. Перезапустите сервер. Проверьте доставку на разрешённый номер. У trial-аккаунтов возможны ограничения получателей и стран.

Ключи не добавляйте в GitHub и не передавайте в браузер. Документация: [отправка Verify](https://www.twilio.com/docs/verify/api/verification), [проверка кода](https://www.twilio.com/docs/verify/api/verification-check).

Сессия — случайный токен в HttpOnly/SameSite cookie; в базе хранится его хеш. На HTTPS cookie получает Secure. Срок сессии — 7 дней. Сервер определяет роль по сессии; заголовки `x-demo-role` и `x-demo-id` не предоставляют доступ.

## Стек и структура

Next.js App Router + React + TypeScript; Prisma + SQLite; Zod; Radix Dialog; Lucide. 3D-эффект реализован CSS без тяжёлого WebGL-движка.

- `components/`: каталог, личные кабинеты, регистрация, профили.
- `lib/auth.ts`: OTP, Twilio, сессии, лимиты.
- `lib/data.ts`: выдача данных с учётом доступа.
- `lib/actions.ts`: бизнес-правила практики.
- `prisma/`: схема и миграции; база создаётся локально.
- `data/seed.json`: исходные 5 кейсов; `data/extra-tasks.json`: ещё 20.
- `public/datasets/`: учебные CSV/JSON и описание.
- `scripts/generate-datasets.mjs`: воспроизводимая генерация датасетов.

AI по умолчанию работает в mock-режиме. OpenAI подключается серверным адаптером Responses API; совместимый Chat Completions адаптер также сохранён. AI предлагает содержание; публикацию и подтверждение делает человек.

## OpenAI: локальная настройка

Сохраните существующий `.env`: не копируйте шаблон поверх него. Добавьте или измените только настройки AI:

```dotenv
AI_MODE="live"
AI_PROVIDER="openai"
OPENAI_API_KEY=""
OPENAI_MODEL="gpt-4.1-mini"
```

Ключ вводится только локально в пустое значение OPENAI_API_KEY, никогда в чат, GitHub или переменную NEXT_PUBLIC.
Доступность модели, действительность ключа и баланс кредитов зависят от аккаунта и не гарантируются кодом.
`OPENAI_MODEL` можно изменить; старое `AI_MODEL` остаётся запасным именем настройки.
Для прежнего провайдера используйте `AI_PROVIDER=compatible` и `AI_BASE_URL`, `AI_API_KEY`, `AI_MODEL`.
После изменения окружения перезапустите сервер.

Явная проверка **одним платным запросом**, только после согласования расходов:

```powershell
npm run ai:check -- --live
```

Скрипт выводит только режим, модель, причину fallback и число вопросов. Ключи и тексты провайдера не печатаются.
Успех — `mode: live`, `provider: openai`. При ошибке возвращается ненулевой код завершения.
Он не проверяет баланс кредита. Схема интеграции основана на официальных документах
[Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs) и
[GPT-4.1 mini](https://developers.openai.com/api/docs/models/gpt-4.1-mini).

При отсутствии ключа, 401/429, отказе модели, неверном JSON, сетевой ошибке или timeout сайт продолжает
работать с детерминированным fallback. Ответ помечен `mode: mock` и `diagnostics.fallbackReason`;
это не настоящий ответ OpenAI. Есть лимит входа, 3–9 разных вопросов, проверка схемы и ссылок на источники,
12 секунд на попытку, максимум один повтор временной ошибки, максимум 3500 выходных токенов.
Запрос отправляется только по действию пользователя. Ответы OpenAI не сохраняются у провайдера через
Responses application storage (`store:false`); это не обещание отсутствия иных служебных журналов провайдера.
Локальная база хранит исходное описание и введённые ответы до обращения к AI.

## Рейтинг, публикация и сохранение

Сервер рассчитывает рейтинг: контекст 10 + потребность 10 + данные 20 + результат 15 + критерии 15 +
ограничения 10 + пользователи 10 + контакт 5 + взаимодействие 5 = 100.
Учитываются только заполненные и подтверждённые поля. Контакт должен содержать email, HTTP(S)-ссылку
или телефон; «білмеймін», «не знаю», пустые строки и одна пунктуация не дают баллов.
Это проверка полноты, а не семантическая оценка качества или достоверности.
Уровни API сохранены: draft (0–39), working (40–69), ready (70–89), priority (90–100).
Ответ `/api/data` дополнен расшифровкой `readiness`: баллы по полям, missingFields и советы.

Редактирование карточки снимает публикацию до нового **Подтвердить сведения → Опубликовать**.
Нерассмотренные изменения не попадают в каталог. Задача и существующие предложения не удаляются.
Публикация требует подтверждённой потребности, но не высокого рейтинга. Низкий рейтинг не блокирует отклики.
Каталог сортируется по убыванию рейтинга, затем даты, затем по ID для одинаковых значений;
поиск и фильтры остаются в существующем клиенте.

Повтор идентичного предложения той же команды возвращает существующую запись, в том числе при
параллельной отправке или после перезапуска. Другую идею/план можно отправить отдельным предложением.
Обычные ссылки — HTTP(S); старые учебные `/demo/prototypes/...` поддерживаются через backend adapter.
Баллы практики отделены от рейтинга: +50 после подтверждения этапа — наше правило MVP.
Проверки прав, решения и начисления выполняются транзакционно, награда уникальна по этапу.

Первоначальные описания и ответы можно получить через приватный `GET /api/drafts`.
Автоматическое восстановление незавершённой формы в интерфейсе ещё требует draft picker от frontend команды.
Полный контракт, примеры запросов, ограничения и задачи для frontend: [docs/BACKEND_CONTRACT.md](./docs/BACKEND_CONTRACT.md).

SQLite подходит для демонстрации и одного постоянно работающего сервера с диском. Для публичной нагрузки нужен отдельный план размещения, постоянное хранилище, резервирование и мониторинг. Не размещайте этот SQLite-файл на эфемерной serverless-файловой системе.

## Проверка

```powershell
npm run typecheck
npm run lint
npm test
npm run build
npm run test:http
```

Тесты используют отдельную временную SQLite-базу. `npm run test:http` после build запускает отдельный
mock-сервер на 3107, проверяет HTTP-сценарий и сохранение после перезапуска. Он не использует рабочую базу,
SMS или платный AI. При занятом порте задайте TEST_HTTP_PORT. Прямой запуск `node scripts/smoke-http.mjs`
по-прежнему создаёт два тестовых аккаунта и проект в базе указанного SMOKE_URL — для обычной проверки
предпочитайте изолированный `npm run test:http`.

Сценарий выступления: [DEMO.md](./DEMO.md). Результаты проверки: [VERIFICATION.md](./VERIFICATION.md).
